HESchema overview

HESchema extends JSON Schema with rules that validate relationships between values in the same JSON document.

When to use it

JSON Schema describes the shape of a document. It can require a citation to have a string sourceId. HESchema can also require that ID to match exactly one entry in the document’s sources array. Use it when individual values can be valid on their own but still disagree with one another.

How validation works

  1. Select a dialect. Set the root $schema to a HESchema dialect that supports your rule. The published dialects extend JSON Schema Draft 2020-12.
  2. Describe the rule. Add a keyword such as localReferences alongside the usual JSON Schema keywords. In the citation example, the rule reads IDs from /citations and matches them against /sources.
  3. Run the HESchema validator. A citation pointing to report-1 passes if exactly one included source has that ID. Change it to a missing ID and the validator reports the offending citation at /citations/0.

Use a validator that implements the selected HESchema vocabulary so the custom rules are evaluated. The Quickstart shows how to run the Python validator with this example.

Choose a keyword

compareFields
Compare two fields, such as a minimum and maximum.
uniqueKeys
Require unique values or combinations of values across array items.
aggregateCompare
Compare a declared count or total with values derived from an array.
localReferences
Require a reference to resolve to exactly one item in the same document.
sortedBy
Check that array items are ordered by a selected key.
nonOverlapping
Reject overlapping intervals in an array.
tensorShapes
Check rank, fixed widths, and shared dimensions across tensors.
arithmeticEquals
Check a supplied arithmetic result using exact decimal strings.

assertExpression is experimental. The reference shows structured JSON and CEL examples. The hosted playground shows recorded outcomes for the native keyword examples.
