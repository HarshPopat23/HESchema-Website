assertExpression

Write cross-field assertions as JSON expression trees. The experimental v1 dialect is implemented in HESchema's Python SchemaEngine. Each expression must evaluate to the Boolean true to pass.

This page describes the implementation merged in HESchema revision 46df47e. It uses the versioned dialect below.

Full schema and data

Every item's quantity must be at most the containing object's limit. Standard JSON Schema keywords establish the required fields and numeric types.

{
  "$schema": "https://raw.githubusercontent.com/HarshPopat23/HESchema-/main/src/heschema/assert-expression-v1.json",
  "type": "object",
  "properties": {
    "limit": {
      "type": "number"
    },
    "items": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "quantity": {
            "type": "number"
          }
        },
        "required": [
          "quantity"
        ]
      }
    }
  },
  "required": [
    "limit",
    "items"
  ],
  "assertExpression": {
    "all": {
      "array": {
        "get": {
          "from": "root",
          "path": "/items"
        }
      },
      "as": "item",
      "test": {
        "lte": [
          {
            "get": {
              "from": "item",
              "path": "/quantity"
            }
          },
          {
            "get": {
              "from": "root",
              "path": "/limit"
            }
          }
        ]
      }
    }
  }
}

Passing data

{
  "limit": 3,
  "items": [
    {
      "quantity": 2
    }
  ]
}

Failing data

{
  "limit": 3,
  "items": [
    {
      "quantity": 4
    }
  ]
}

The failing assertion reports ASSERT_EXPRESSION_FALSE. The instance location is the containing object, the empty JSON Pointer. V1 does not automatically report /items/0/quantity.

Run locally

Follow the Quickstart to install the pinned validator. Save the schema above as schema.json and either data example as data.json.

import json
from pathlib import Path
from heschema.schema import SchemaEngine

schema = json.loads(Path("schema.json").read_text())
data = json.loads(Path("data.json").read_text())
errors = SchemaEngine().errors(schema, data)
print(json.dumps({"valid": not errors, "errors": errors}, indent=2))

The passing data returns {"valid": true, "errors": []}. With the failing data, valid is false and errors includes the assertion diagnostic. The hosted playground currently has recorded examples for the eight dedicated keywords. Use the local Python example for this dialect.

Every operator

An expression is an object with exactly one operator. Operands are expressions. The contents of literal and pointer/binding metadata are data.

OperatorArgumentsBehavior
literalAny JSON valueReturn the value without interpreting its members.
getfrom and pathResolve a pointer in a named binding. Missing values produce an evaluation error.
existsfrom and pathTrue when the pointer resolves, including to null or an empty string.
eq, neExactly two expressionsStructural equality and inequality.
lt, lte, gt, gteExactly two expressionsStrict ordering of finite numbers. Strings and booleans fail.
notOne expressionNegate a Boolean.
and, orNonempty expression arrayEvaluate Boolean operands left to right and short-circuit.
iftest, then, elseEvaluate a Boolean test and only the selected branch.
all, somearray, as, testEvaluate the test with a named binding for each visited item.

all on an empty array returns true; some on an empty array returns false. Add minItems: 1 when an item is required.

Pointers and scope

Root is the instance at the schema containing the assertion. At the schema root this is the document. Under items or a local reference it is the item or object being validated. It does not automatically refer to the outermost document.

  • /a.b selects a literal dotted member; /a/b selects a nested member.
  • / selects an empty member name. The empty pointer selects the binding itself.
  • ~1 escapes a slash and ~0 escapes a tilde.
  • Array indices must use canonical nonnegative integers, such as 0 or 12.

All and some introduce a fresh identifier with as. A nested predicate retains access to root and enclosing predicate bindings. Reusing root or an enclosing name is rejected. Bindings never execute user code.

Registration and errors

Use SchemaEngine so registration checks operator names, operand counts, pointers and lexical bindings in every branch. An unknown operator in an unused else branch is still rejected. Meta-schema validation alone does not perform all these checks.

  • Invalid schema raises ValueError during registration. Examples include an unknown operator, an unbound name, malformed pointer or wrong argument count.
  • ASSERT_EXPRESSION_FALSE means a valid rule evaluated to false.
  • ASSERT_EXPRESSION_ERROR means an operand type, missing get pointer, final result type or evaluation budget failed.

Runtime type checks are performed only on evaluated branches. V1 has no static type inference. For example, or with literal true skips a missing-pointer operand, while registration still checks that skipped operand's structure.

SchemaEngine diagnostics include keyword assertExpression, instanceLocation, schemaLocation and evaluationLocation. The two assertion reason identifiers currently appear in message text. The outer diagnostic code remains the existing SCHEMA_INVALID. Per-item expression provenance and dedicated machine-readable reason fields are future work.

Limits and compatibility

  • Expression operator nesting is limited to 48. Evaluation allows 10,000 visited expression nodes, shared across predicates.
  • Existing schema and instance complexity limits also apply. Literal content is handled as data.
  • Objects compare independently of member order; arrays compare in order. Boolean true differs from numeric 1; 1 equals 1.0.
  • Python integers preserve precision. Floats retain the precision already supplied by the JSON parser. Rounded input cannot be recovered by an expression.
  • The standalone assertion dialect includes standard Draft 2020-12 validation and assertExpression. It does not combine the eight dedicated keywords.
  • Declare the dialect at the schema root. Custom dialects use one schema resource and local static references. Nested dialect switches and external references are rejected.
  • This dialect runs in the Python backend. The optional Blaze backend and provider constrained decoding do not implement its custom evaluator.

A passing assertion proves the supplied relationship. Comparing an extracted value with an original invoice still requires independently trusted source data.

The 15-gap roadmap

V1 supports arbitrary pointer keys, literal values, presence checks, structural equality, lexical predicate scope, empty-array semantics, strict numeric operands and lazy built-in conditionals. Registration checks every branch's structure and basic assertion diagnostics are available.

Dynamic regex, civil-date and timestamp operators, exact decimal expressions, Unicode slicing and custom lazy extensions remain future work. Exact numeric fidelity also depends on ingestion. Per-item diagnostics and static type inference remain limited. This custom JSON expression language is separate from the proposed stock JsonLogic experiment in Blaze.
